ek.agents.base#

Agent-evaluation data shapes: the episode (Layer B) and the task/tool grammar (Layer A).

Evaluating an agent is the same two-layer problem ek already solves for information extraction – only the evaluated object changes. An extraction is a static payload; an episode is a process: a sequence of tool calls and observations ending in a final state. So:

  • Layer A – the task/tool grammar. ToolSpec and TaskSpec are builders over the existing GraphGrammar: a tool becomes a NodeType whose fields are its argument FieldSpec s,

    and importance carries the cost of getting that argument wrong. A wrong argument to a destructive tool is not one unit of error. This reuses the Layer-A cost-weight SSOT rather than inventing a parallel schema.

  • Layer B – the episode. Episode carries the Trajectory, the Cost, the outcome, and the RunProvenance – riding alongside the

    frozen grammar, never mutating it, exactly as AnnotatedExtraction does.

These shapes live here, not in ek.base: that module is the zero-dependency, IE-schema-only SSOT, and the OCR instance sets the precedent that an instance’s concrete shapes stay out of core (core duck-types them). Nothing here is imported by ek core.

Example

>>> from ek.base import FieldSpec
>>> book = ToolSpec("book_flight", params={"flight": FieldSpec("flight", "string"),
...                                        "seat": FieldSpec("seat", "string")})
>>> refund = ToolSpec("refund", params={"amount": FieldSpec("amount", "number",
...                                     importance=20.0)}, destructive=True)
>>> g = tool_grammar(book, refund)
>>> g.field_cost("refund", "amount")        # a wrong refund amount is expensive
20.0
>>> g.field_cost("book_flight", "seat")     # a wrong seat is not
1.0

See misc/docs/ek_07 (the map) and misc/docs/ek_12 (the integration report).

class ek.agents.base.Cost(input_tokens=0, output_tokens=0, cached_input_tokens=0, reasoning_tokens=0, retries=0, latency_s=None)[source]#

Bases: object

What one episode consumed: tokens (by kind), retries, and wall-clock.

Token kinds are tracked separately because they are priced asymmetrically – output typically costs ~5x input, cached input bills at a fraction, and reasoning tokens are billed. This is precisely why the objective is dollars per successful task and never a raw token count (misc/docs/ek_11). Pricing lives in ek.agents.cost; this dataclass is the provider-neutral tally.

Example

>>> a = Cost(input_tokens=100, output_tokens=50)
>>> b = Cost(input_tokens=10, output_tokens=5, retries=1)
>>> c = a + b
>>> c.input_tokens, c.output_tokens, c.retries
(110, 55, 1)

ek.agents.base.DESTRUCTIVE_WEIGHT = 10.0#

Multiplier applied to a destructive tool’s importance when it is not set explicitly. Calling a destructive tool wrongly is categorically worse than calling a read-only one; a keyword-tunable default, never a magic number buried in a metric.

class ek.agents.base.Episode(task_id='', trajectory=<factory>, output=None, final_state=None, cost=None, success=None, run=None, provenance=None, meta=<factory>)[source]#

Bases: object

Layer B: one agent run over one task – the object agent evaluation scores.

The direct analog of AnnotatedExtraction: it rides alongside the frozen Layer-A grammar and carries the run’s metadata. It is scored offline against gold (ek.score() / ek.evaluate()) and estimated online against a judge or a consensus (ek.estimate_quality()) – the same object, both halves.

Parameters:

  • task_id (str) – Which task this episode answers (the k-trial grouping key).

  • trajectory (Trajectory) – The tool calls taken.

  • output (Any) – The agent’s final user-facing answer.

  • final_state (Any) – The end state of the world (the DB, the filesystem) – what a state-based oracle actually grades. Success is a final-state check, not a surface-text check.

  • cost (Optional[Cost]) – The Cost consumed.

  • success (Optional[bool]) – Filled in by a checker; None until graded.

  • run (Optional[RunProvenance]) – The RunProvenance (seed, model, simulator, suite version).

  • provenance (Optional[Provenance]) – Optional core Provenance for click-to-source audit.

  • meta (dict) – Anything else the bridge captured.

property calls: tuple#

class ek.agents.base.RunProvenance(seed=None, temperature=None, model='', simulator='', suite_version='', scaffold='')[source]#

Bases: object

The hidden eval variables that decide whether two runs are even comparable.

Agent evaluation is stochastic, and several of its inputs are themselves models. In a tau-bench-style suite the user simulator is an LLM agent, so its model/prompt/version silently changes results run to run. Recording these is what lets the harness refuse to compare a baseline against a run that changed the simulator or the suite – the same discipline ek’s offline harness already applies when it refuses to compare across two different metrics (misc/docs/ek_08, misc/docs/ek_11).

Parameters:

  • seed (Optional[int]) – RNG seed for the trial (None = unseeded/nondeterministic).

  • temperature (Optional[float]) – Sampling temperature of the agent under test.

  • model (str) – The agent’s model id.

  • simulator (str) – The user-simulator id/version – an eval variable, not a constant.

  • suite_version (str) – Version of the task suite (contamination and task fixes move scores).

  • scaffold (str) – The agent scaffold/harness id (the same model moves points on scaffold alone).

comparability_key()[source]#

The fields that must match for two runs to be comparable (seed excluded).

Seed and temperature are expected to vary across trials; the simulator, the suite version and the scaffold are not – changing them invalidates a baseline.

tuple

class ek.agents.base.ToolSpec(name, params=<factory>, importance=None, destructive=False)[source]#

Bases: object

One tool the agent may call: its argument schema and its error costs.

Parameters:

  • name (str) – The tool/function name (the AST-match ground truth).

  • params (Mapping[str, FieldSpec]) – Argument name -> FieldSpec. Each spec’s importance is the cost of getting that argument wrong, and its domain feeds validators – the same contract as an extracted field.

  • importance (Optional[float]) – Cost weight of the call itself (a missing or spurious call). Defaults to DESTRUCTIVE_WEIGHT when destructive is set, else 1.0.

  • destructive (bool) – Whether calling this tool mutates the world irreversibly (a refund, a delete, a send). Drives the default weight and the safety validators.

class ek.agents.base.Trajectory(steps=())[source]#

Bases: object

The ordered sequence of Step s an agent took.

A trajectory is linear – which is why it is scored with a sequence edit distance, not a graph edit distance (see ek.agents.trajectory).

Example

>>> t = Trajectory([Step("search", {"q": "cat"}), Step("answer", {"a": "meow"})])
>>> len(t), t.tools

ek.agents.base.as_call(x)[source]#

Coerce a Step, (tool, args) tuple, or {"tool":…, "args":…} dict.

Gold tool calls are usually written as bare pairs or dicts (no observation), while a prediction arrives as a Step; both must compare. Progressive disclosure: the simple literal works, the rich object works.

Return type:

tuple

Example

>>> as_call(Step("search", {"q": "cat"}))
('search', {'q': 'cat'})
>>> as_call(("search", {"q": "cat"}))
('search', {'q': 'cat'})
>>> as_call({"tool": "search", "args": {"q": "cat"}})
('search', {'q': 'cat'})
>>> as_call("search")
('search', {})

ek.agents.base.tool_grammar(*tools)[source]#

Build the Layer-A GraphGrammar from ToolSpec s.

The resulting grammar is the frozen cost SSOT every agent metric reads: node cost = the tool’s call weight, field cost = the argument’s importance.

Return type:

GraphGrammar

Example

>>> from ek.base import FieldSpec
>>> g = tool_grammar(ToolSpec("send", params={"to": FieldSpec("to")},
...                           destructive=True))
>>> g.node_cost("send")
10.0
