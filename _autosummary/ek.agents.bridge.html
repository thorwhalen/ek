ek.agents.bridge#

One-way adapters: turn whatever your agent already emits into an ek Episode.

The dependency direction is the ek -> ocracy rule restated, and it is a hard rule: ek -> inspect_ai / deepeval / ragas (via the ek[agents] extra), never the reverse.

Note what that buys: ek core depends only on the shape of what those tools emit, so the adapters here duck-type and import nothing. You need the extra to run Inspect or DeepEval; you do not need it to score what they produced – exactly as ek evaluates any OcrResult-shaped object without importing an OCR engine.

The workhorse is trajectory_from_messages(): provider-shaped chat transcripts (OpenAI- and Anthropic-style tool_calls / tool_use blocks) are the universal wire format for a tool-using agent, and parsing them needs no SDK at all.

Example

>>> messages = [
...     {"role": "user", "content": "weather in Paris?"},
...     {"role": "assistant", "tool_calls": [
...         {"function": {"name": "get_weather", "arguments": '{"city": "Paris"}'}}]},
...     {"role": "tool", "content": "18C"},
...     {"role": "assistant", "content": "It is 18C in Paris."},
... ]
>>> traj = trajectory_from_messages(messages)
>>> traj.tools
('get_weather',)
>>> traj.steps[0].args, traj.steps[0].observation
({'city': 'Paris'}, '18C')

ek.agents.bridge.episodes_from_inspect_log(log, *, scorer=None, success_threshold=1.0, task_prefix='')[source]#

Yield one graded Episode per sample per epoch of an Inspect EvalLog.

task_prefix (e.g. the Inspect task name) is prepended as "<prefix>/<sample id>" – needed when pooling several logs, whose sample ids (often 1, 2, 3) would otherwise collide and be counted as extra trials of one task. A scorer that no sample has raises ValueError (a typo would otherwise leave every episode silently ungraded).

Duck-typed like from_inspect_sample() (no inspect_ai import): reads log.samples and log.eval. Each sample’s score – the scorer named, else the first – is read with inspect_score_value() and the episode is graded success = value >= success_threshold; a sample with no scalar score stays ungraded (success=None) rather than being silently counted as a failure.

Inspect’s epochs are ek’s trials: an eval run with epochs=k yields k episodes per task_id (the sample id), which is exactly what reliability() needs for pass^k. The run’s model and task version are recorded as RunProvenance.

Example (a log-shaped stand-in; a real EvalLog has the same attributes):

>>> from types import SimpleNamespace as NS
>>> sample = NS(id="q1", epoch=1, messages=[], output=NS(completion="4", usage=None),
...             scores={"match": NS(value="C")})
>>> log = NS(samples=[sample], eval=NS(model="mockllm/model", task_version=0))
>>> [(e.task_id, e.success, e.meta["epoch"]) for e in episodes_from_inspect_log(log)]
[('q1', True, 1)]
Return type:

Iterator[Episode]

ek.agents.bridge.trajectory_from_messages(messages)[source]#

Parse a chat transcript into a Trajectory.

Each assistant tool call becomes a Step, and the next tool/result message becomes that step’s observation. A tool message carrying an error marks the step as errored – error recovery across later steps is itself an evaluable signal.
